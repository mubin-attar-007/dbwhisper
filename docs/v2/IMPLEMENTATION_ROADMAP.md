# DBWhisper v2 — Implementation Roadmap

> Branch: `feat/dbwhisper-v2` · started 2026-08-21 · status legend: ☐ planned · ◐ in progress · ☑ done (with evidence)
> Each phase ends with: tests passing, docs updated, a log entry in §Implementation log at the bottom.

## Breaking changes on this branch

* **Enrolling a database now requires `DBW_SECRET_KEYS`** in `self_hosted` and `production` modes.
  Storing a connection string in the clear is no longer possible, per the brief's non-negotiable on
  credentials. Generate a key with `uv run python -m app.platform.secrets generate-key`. Existing
  rows keep working (reads fall back to the legacy plaintext column) and are encrypted in place at
  startup once a key is present; only *new* enrollments are refused without one.
* **`EMBEDDING_PROVIDER` is deprecated** in favour of `EMBEDDING_PROFILE`. The old variable is still
  read and mapped, with a warning.

## Guiding rules for every phase

1. Inspect before replacing; keep healthy code, refactor weak abstractions, replace unsafe behaviour.
2. Persisted data is migrated (Alembic), never deleted.
3. Existing v1 routes keep their contracts; new behaviour goes to `/v2`.
4. Nothing requires a paid service to start, test, demo, evaluate, build or run CI.
5. Every security-relevant change ships with a negative test.
6. Every public claim changed or added is recorded in `CLAIM_AUDIT.md`.

## Phase 1 — Platform foundation ☑

* `app/platform/settings.py` — extend `Settings` with `APP_MODE`, `DBW_SECRET_KEYS`, local-AI settings

* `app/platform/secrets.py` — MultiFernet encryption; `encrypt_secret/decrypt_secret`; key rotation CLI.
* Alembic: baseline migration autogenerated from today's models; migration `0002` adds
  `data_sources.connection_secret` (encrypted) and backfills from plaintext, leaving the old column

  `langchain-community` and `groq` if unused (per license audit); add `sqlglot`, `alembic`,
  `cryptography`, `httpx` (already transitive), `hypothesis` (dev), `opentelemetry-*`,
  `prometheus-client`, `fastembed`. Update `DEPENDENCY_AND_LICENSES.md`.
* Fix the import-time breakages found in the audit (`user_database_manager.py`,
  `warn_on_readonly_mismatch`), delete confirmed-dead code, replace the hard-coded AvasMed prompt with a

  and (optional job) Postgres.

## Sequencing rationale

Policy engine (2) and execution service (3) come before the model layer (4) so every later phase runs
through hardened paths from day one. Retrieval (5) precedes the graph (6) because the graph's context
pack depends on it. Evaluation (8) follows the graph so the smoke set exercises the real pipeline, but
the adversarial corpus is authored in Phase 2 because it gates the policy engine.
